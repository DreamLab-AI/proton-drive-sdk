# Audit — 2026-07-05 gap-fill mesh

**Branch:** `audit/gap-fill` (merges `wp1`–`wp6`, `wp9`; this document is
part of `wp7`, the documentation-reconciliation pass).
**Scope:** the Rust port only (`rust/`), reviewed against `reference/client/js`
as the wire-format and behavioural ground truth (ADR-0001).

This is a short summary. For current per-milestone state read
[`IMPLEMENTATION-STATUS.md`](./IMPLEMENTATION-STATUS.md); for protocol-level
detail read the affected ADRs (`adr/0006`, `adr/0008`, `adr/0009`, `adr/0011`).

## The audit

A 90-agent mesh — organised into finder/verifier roles across parallel work
streams (`wp1`–`wp6`, `wp9`, landed as the fix packages below; `wp7` is this
documentation-reconciliation pass; `wp8`, tests-residual, is a separate,
independently tracked work package outside this pass's scope) — read the
Rust port line-by-line against `reference/client/js`, raised candidate findings,
and independently re-verified every candidate against the actual source
before it counted.
Result: **38 confirmed findings, 0 refuted**. A number of findings were
confirmed as real but had their severity *corrected downward* on
verification (typically from "high" to "medium" or "low") once cross-checked
against reachability and actual runtime consequence — a defect that is real
but doc-only, or real but already load-bearing-tested and merely mislabeled,
does not carry the same weight as a live protocol or security bug. That
distinction is preserved in `IMPLEMENTATION-STATUS.md`'s blocker table rather
than collapsed into a single severity number.

Fix packages landed for every confirmed finding judged worth acting on now;
see the per-package summary below. Two categories of finding were
**confirmed but deliberately not fixed** — recorded as known gaps rather than
silently dropped:

- The v1→v2 endpoint migration (see below) — real, but out of scope for a
  docs/audit pass and lower-urgency than the crypto/transport/session fixes.
- B5 (detached per-block signature not independently verified) — on
  investigation this turned out not to be a bug at all: the JS reference has
  no code path that verifies it either. Recorded as JS-faithful-by-design,
  not fixed because there was nothing to fix.

## Fixes landed, by work package

- **wp1 (nodes/errors):** corrected the API error taxonomy — `2500` now maps
  to `AlreadyExists` (name collision) instead of a generic error; `2011` maps
  to a new `PermissionDenied` variant instead of being folded into an
  unrelated one.
- **wp2 (HTTP transport):** added 429 retry honouring `Retry-After` instead
  of failing hard; stopped leaking the `Authorization: Bearer` token and
  `x-pm-uid` header onto storage `BareURL`s (blocks are served from a
  different host than the API — those headers had no business going there).
- **wp3 (download/transfer):** paginated block-list fetch (`PageSize`/
  `FromBlockIndex`), so large revisions no longer silently truncate; download
  now cleans up a partial file on mid-stream failure (B6, was open);
  `signature_verified` is surfaced in `pdtui`'s UI instead of only living in
  `DownloadStats`; filename sanitisation closes a path-traversal gap;
  `NodePassphraseSignature` and `ContentKeyPacketSignature` are now verified
  JS-faithfully (non-fatally — see ADR-0009); B5 (above) documented as
  JS-faithful non-verification rather than "fixed"; the upload progress gauge
  (stuck/incorrect) fixed.
- **wp4 (upload):** failed uploads now clean up the orphaned server-side
  draft (`DeleteDraft`) instead of leaving it behind; removed a redundant
  inline block signature check that had no JS counterpart (detached-signature
  handling is the only JS-faithful path); the SHA1 checksum comparison is now
  actually performed instead of computed-and-ignored.
- **wp5 (auth/session):** enabled a real OS-keyring backend on
  linux-native/apple-native/windows-native (file fallback retained for
  platforms without one); `SessionExpired` now wipes the 0600 secret file and
  `session.json`, not just the (best-effort) keyring entry; concurrent 401
  responses now coalesce into a single in-flight `/auth/refresh` request
  instead of firing one per caller; the interactive-login password is
  wrapped in `Zeroizing`; the server's `ExpiresIn` is honoured on both
  `/auth` and `/auth/refresh` instead of a hardcoded fallback.
- **wp6 (crypto):** XAttr/manifest decrypt now decompresses before signature
  verification, so JS `compress: true` payloads verify correctly instead of
  failing; `EncryptOptions.compress` is wired through instead of ignored;
  `Zeroizing<String>` at the `generate_passphrase` trait boundary; key
  material gets a redacted `Debug` impl instead of leaking bytes into logs;
  an explicit, independently-testable `reject_seipd_v2` guard replaces the
  previous incidental rejection (see ADR-0006); a new compressed-payload wire
  fixture was added (ADR-0012).
- **wp9 (pdtui/events):** `subscribe_drive_events` is now wired into
  `pdtui`'s remote pane (`apps/pdtui/src/events_bridge.rs`) — a relevant
  drive event flips a staleness flag the UI checks once per redraw tick,
  with graceful degradation to the original pull-on-focus behaviour if the
  subscription fails to establish.

## Deliberately deferred (not fixed, and why)

- **v1→v2 endpoint migration.** `client.rs`'s `node`, `fetch_folder_children`,
  `resolve_node_key_via_chain`, and `file_downloader` all call the
  `@deprecated`-marked legacy share-scoped endpoints
  (`/drive/shares/{shareID}/links/{linkID}`,
  `/drive/shares/{shareID}/folders/{linkID}/children`) rather than the v2
  volume-scoped, cursor-paginated endpoints
  (`/drive/v2/volumes/{volumeID}/folders/{linkID}/children` + batched
  `POST /drive/v2/volumes/{volumeID}/links`) that
  `reference/client/js/src/internal/nodes/apiService.ts` actually uses in
  production. This works correctly today — the live round-trip proved it —
  but carries real forward-compatibility risk: Proton could retire the
  deprecated routes without notice, and the v2 response shape
  (`LinkIDs`/`More`/`AnchorID` cursor pagination) is materially different
  from the flat `Links[]`/page-index `GetChildrenResponse` the current Rust
  DTOs model, so this is a DTO-and-client rewrite, not a one-line fix.
  Tracked as **B8** in `IMPLEMENTATION-STATUS.md`. Deferred pending live
  re-validation of the wp1–wp9 fixes first — no point layering a bigger
  migration on top of an unverified base.
- **B5 — detached per-block signature not independently verified.** Not a
  bug: `reference/client/js`'s own `cryptoService.ts` never fetches or verifies
  it either. Per-block data integrity is (correctly) established by the
  SHA-256 ciphertext hash check instead; per-revision authenticity is
  established by the manifest signature over all block hashes. Documented as
  JS-faithful by design in `IMPLEMENTATION-STATUS.md` and ADR-0009, not
  "fixed" because nothing was broken.
- **Nested-folder upload (B2, upload half).** `upload.rs::resolve_parent_context`'s
  own doc comment states it is only correct when the parent is the share
  root. Download and folder-listing (`client.rs::resolve_node_key_via_chain`)
  correctly walk the full parent chain at any depth (646 MB nested-file
  download live-verified), but upload's parent-key resolution was not
  extended to match during this pass. Real, current, and open — tracked as
  the upload half of **B2**.
- **Live re-validation of the full round-trip.** Every fix above is
  unit/wire-tested; **none has been re-proven against a live Proton account
  since landing**. Nothing in the wp1–wp9 diffs touched the core protocol
  shape, but that is an assumption, not a proof. Re-running `pdtui mvp`
  against a real account is the single highest-value next step before
  trusting this state end-to-end — see `HANDOFF.md`.

## Test totals

| | Passed | Failed | Ignored |
|---|---|---|---|
| Baseline (measured at audit start, pre-fix, on `audit/gap-fill`) | 122 | 0 | 6 |
| Post-fix (current, `wp1`–`wp6` + `wp9` merged) | 192 | 0 | 6 |

The baseline of 122 is the count at the point this audit began — already
higher than the "85 passing" figure in older status-doc snapshots, which
predated the M6 events-consumer work landing. The post-fix growth (122 → 192)
is concentrated in wp3 (download/transfer edge cases), wp5
(session/keyring/coalescing), and wp6 (crypto compression + `reject_seipd_v2`)
new test coverage. The 6 ignored tests are unchanged across both counts —
all require external state (a live account, Node.js + the `openpgp` npm
package, or explicit `--ignored` opt-in for timing-sensitive cases) and are
ignored by design, not by neglect.
